Guias práticos

Instalação dos programas recomendados

Passo a passo básico para instalar as principais alternativas open-source citadas no conteúdo principal do site.

  • Firefox — baixe direto do site oficial (mozilla.org/firefox) ou pela loja de aplicativos do seu sistema operacional. Em distribuições Linux, geralmente já vem pré-instalado.
  • VLC Media Player — disponível em videolan.org, com instaladores para Windows, macOS e Linux. Em distros baseadas em Debian, pode ser instalado via apt install vlc.
  • LibreOffice — baixe em libreoffice.org. O instalador já inclui todos os módulos (Writer, Calc, Impress).
  • F-Droid — baixe o APK direto em f-droid.org (não está disponível na Google Play Store, por princípio). É necessário permitir instalação de fontes desconhecidas no Android.

Como verificar a integridade de um download

Verificar se o arquivo baixado é exatamente o que o projeto publicou (e não foi alterado no meio do caminho) é uma prática recomendada, especialmente em downloads fora de lojas oficiais.

  • Checksum SHA-256 — o site do projeto geralmente publica um hash SHA-256 do arquivo. Depois de baixar, gere o hash do arquivo localmente e compare:
    Linux/macOS: sha256sum arquivo.AppImage
    Windows (PowerShell): Get-FileHash arquivo.exe -Algorithm SHA256
    Se os dois valores não forem idênticos, não instale o arquivo.
  • Assinatura GPG — alguns projetos assinam os arquivos com uma chave GPG. Isso confirma não só que o arquivo não foi alterado, mas que veio realmente do mantenedor do projeto. Requer importar a chave pública do projeto e rodar gpg --verify sobre o arquivo de assinatura.

Guia de migração

Trocar de software proprietário para open-source costuma ser mais simples do que parece — a maioria das alternativas foi desenhada para ser familiar a quem vem de outra ferramenta.

  • Chrome → Firefox: o Firefox importa favoritos, senhas e histórico automaticamente na primeira execução.
  • Microsoft Office → LibreOffice: abre e salva arquivos .docx, .xlsx e .pptx nativamente, então não é necessário converter os arquivos existentes.
  • WhatsApp → Signal: é possível importar o histórico de conversas do WhatsApp durante a configuração inicial do Signal, tanto no Android quanto no iOS.
  • Photoshop → GIMP: a curva de aprendizado é a maior desse grupo — os atalhos e o fluxo de camadas são diferentes, vale procurar um guia de conversão de atalhos.

Referência técnica

Glossário

  • Código aberto (open-source): software cujo código-fonte é público e pode ser lido, modificado e redistribuído por qualquer pessoa.
  • Telemetria: dados de uso enviados automaticamente por um programa para os servidores de quem o desenvolveu.
  • Backdoor: uma porta de acesso oculta em um software, que permite que alguém entre no sistema sem passar pelas verificações normais.
  • Fork: uma cópia independente de um projeto open-source, criada por outra pessoa ou comunidade a partir do código original.
  • Auditoria de código: processo de revisar o código-fonte de um programa em busca de falhas de segurança ou comportamentos indevidos.
  • Zero-trust: princípio de segurança que parte do pressuposto de que nada deve ser confiado por padrão — tudo precisa ser verificado.
  • Upstream: o repositório ou projeto original do qual uma cópia, fork ou pacote foi derivado.
  • Licença livre: licença legal que garante ao usuário o direito de usar, estudar, modificar e redistribuir um software (ex: GPL, MIT, Apache).

Perguntas frequentes

Open-source é sempre mais seguro?

Não automaticamente. O código estar aberto só melhora a segurança se alguém de fato o revisar. Projetos grandes e ativos (como Firefox ou LibreOffice) têm muitos olhos auditando o código constantemente. Projetos pequenos ou abandonados podem ter falhas que nunca foram encontradas, mesmo com o código público.

Como sei que o programa que eu instalei bate com o código publicado?

Na prática, é difícil confirmar isso sozinho sem conhecimento técnico avançado. O que dá pra fazer é: baixar sempre do site oficial ou de repositórios confiáveis (nunca de sites de terceiros), conferir o checksum quando disponível, e confiar no processo de build reprodutível que alguns projetos oferecem — quando o código-fonte, compilado por qualquer pessoa, sempre resulta no mesmo arquivo binário.

Open-source custa dinheiro?

Na grande maioria dos casos, não — o software em si é gratuito. Alguns projetos oferecem versões pagas com suporte técnico, hospedagem gerenciada ou recursos extras (é o chamado modelo "open-core"), mas a base do software continua livre e gratuita.

Para quem quer ir além

Como contribuir com um projeto open-source

Contribuir não exige saber programar. Formas comuns de ajudar um projeto:

  • Reportar bugs: a maioria dos projetos usa GitHub ou GitLab, com uma seção de "Issues" para relatar problemas encontrados.
  • Traduzir: muitos projetos usam plataformas como Weblate ou Crowdin, onde qualquer pessoa pode sugerir traduções.
  • Revisar código: para quem programa, revisar "pull requests" de outras pessoas é uma forma valiosa de contribuição, mesmo sem escrever código novo.
  • Documentar: escrever ou corrigir a documentação de um projeto costuma ser bem-vindo e não exige conhecimento profundo do código.

Como avaliar a reputação de um projeto

Antes de confiar em um software open-source pouco conhecido, alguns sinais ajudam a diferenciar um projeto sério de um abandonado ou suspeito:

  • Data do último commit — projetos sem atividade há anos podem ter vulnerabilidades não corrigidas.
  • Número de colaboradores — projetos mantidos por uma única pessoa são mais frágeis e mais fáceis de comprometer.
  • Histórico de issues respondidas — indica se a comunidade ou mantenedores realmente acompanham o projeto.
  • Licença clara e visível no repositório — a ausência de licença é um sinal de alerta.
  • Presença em repositórios curados, como o F-Droid, que tem critérios próprios de inclusão.
